Mas encontrei três pontos que eu corrigiria.

O primeiro é que o `MockMcpClient` tem esta linha:

```ts
if (!args) { /* dummy */ }
```

Isso é um sinal de que o parâmetro `args` só está ali para satisfazer o linter. É melhor remover esse dummy de forma limpa. Como `args` faz parte do contrato, o mock pode guardar o último input recebido, ou validar que `args` é objeto, ou usar `_args` se a configuração permitir. O ideal é adicionar capacidade de inspeção, como `getCalls()`, porque isso ajuda os próximos testes de agentes. Assim, na Fase 8, dá para verificar se o agente chamou a ferramenta correta com os argumentos corretos.

O segundo ponto é que `setTools` não valida o schema das ferramentas. Se passar uma ferramenta malformada, o mock aceita. A Fase 7 diz que valida contratos MCP, então eu esperaria validação também em `setTools`, ou pelo menos um teste que garanta que tool sem `name` não entra.

O terceiro ponto é que `McpCallResult` permite estados contraditórios, como `{ ok: true, error: {...} }` ou `{ ok: false, content: {...} }`. O Zod atual só verifica campos opcionais, mas não garante a relação correta entre `ok`, `content` e `error`. O ideal é um contrato discriminado: se `ok: true`, pode ter `content` e não deve ter `error`; se `ok: false`, deve ter `error` com `retryable`. Isso vai evitar problemas quando os agentes começarem a depender dessa resposta.
